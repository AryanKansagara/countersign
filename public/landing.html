This is what a risky change looks like

Our test agent tried to reassign 12 leads. Its limit without approval is 5, so it stopped and asked.

Why we built it

In April, a coding agent deleted a company's production database and its backups in one API call. Giving agents read-only access avoids that, but then they can't do much. We wanted agents that can write, with the checks a pull request gets.

We attacked it

Same attack twice: once with a plain MongoDB connection, once through Countersign. The script is in the repo (npm run attacks).

Connecting takes one key

Sign in with GitHub, request a key for your agent, and someone else on your team approves it. Then paste it into Claude Code, Claude Desktop, claude.ai, Cursor, VS Code or ChatGPT. The app has copy-paste setup for each.

# Claude Code
claude mcp add --transport http countersign https://.../mcp --header "x-agent-key: cs_agent_..."

# ChatGPT or claude.ai (they can't send headers, so the key goes in the URL)
https://.../mcp/cs_agent_...

How it uses MongoDB Atlas

Each change runs in a transaction that re-checks the records and aborts if anything moved. Change streams power the live log and flag writes that skipped Countersign. Vector Search compares a new change with past approved ones. The audit log is hash-chained, and the database user Countersign runs as can only add to it, not edit it. Temporary permissions expire through TTL indexes.

Not done yet

Agents connect with a key, not a "Sign in with GitHub" button inside Claude or ChatGPT. It only works with MongoDB. The demo banks and their keys are public on purpose so anyone can try it, so don't put real data in the demo.
