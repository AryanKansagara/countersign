// THE PROBLEM

Agents can read your database. Letting them write is how production gets deleted.

April 2026: a coding agent deleted a company's production database and its backups in one API call. It took nine seconds.

The usual fix is "read-only", which removes most of an agent's value, and read-only flags inside MCP servers have been bypassed anyway. Humans get pull requests, reviews, least privilege, undo and audit logs. Agents get a connection string.

Countersign gives agent writes the same safeguards as code changes.

// HOW IT WORKS

Propose → check → dry run → approve → apply → verify → undo

Propose
The agent calls propose_change and must say how many records it means to touch.
Check
Rights = agent scope ∩ the human it acts for. Fields, ops and operators are validated.
Dry run
Counts the real matches. "Expects 3, matches 4,000" is blocked on the spot.
Approve
Small, routine changes auto-apply. Risky ones wait for a different human with a PR-style diff.
Apply + verify
One transaction re-checks versions, writes, and verifies only the declared fields changed.
Undo
Before-images make every applied change one-click reversible.
